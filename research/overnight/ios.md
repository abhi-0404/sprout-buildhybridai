## 1. Firebase Apple hybrid and Foundation Models: status
- Hybrid (HybridModel + FirebaseAI.SystemLanguageModel + GenerativeModelSession) needs Firebase Apple SDK >= 12.13.0 (public preview since 12.13.0, May 5 2026), Swift Package Manager only, no CocoaPods. [V] https://firebase.google.com/docs/ai-logic/hybrid/ios/get-started and https://firebase.google.com/support/release-notes/ios
- 13.0.0 (Oct 7 2026) removed HybridModel, SystemLanguageModel, GenerativeModelSession; replacement is ai.geminiLanguageModel(name:) for Apple's LanguageModelSession. Latest 12.x is 12.19.3 (Oct 22 2026); latest 13.x is 13.2.0 (Nov 16). [V] same release notes. The repo pin "12.13.0 ..< 13.0.0" is right; prefer resolving to 12.19.3 (bug fixes since 12.13) [U that 12.19.3 still has hybrid, 12.x line is not stated to have removed it].
- Minimum Xcode: officially supported minimum is Xcode 26.2 (Swift 6.2.3 toolchain) since 12.12.0. [V] release notes. The Firebase get-started page prints no Xcode or iOS minimum. [V]
- Module name: FirebaseAI was renamed FirebaseAILogic in 12.5.0; product to add is FirebaseAILogic (+ FirebaseAppCheck). [V] release notes + get-started. So Swift line 3 "VERIFY" is resolved.
- Foundation Models: iOS/iPadOS/macOS 26+, Apple Intelligence compatible device with Apple Intelligence turned on (iPhone 15 Pro/Pro Max and all iPhone 16/17 families; iPhone 15 and older cannot). https://www.apple.com/newsroom/2025/09/apples-foundation-models-framework-unlocks-new-intelligent-app-experiences/ [V for "AI-compatible + enabled + OS 26"; iPhone list is [U], from memory, and research/02 line 74 says the same].
- Availability reasons: .available, .unavailable(.deviceNotEligible | .appleIntelligenceNotEnabled | .modelNotReady). [V] https://firebase.google.com/docs/ai-logic/hybrid/ios/configuration-options (Firebase wraps the same cases; also FirebaseAI.SystemLanguageModel.default.isAvailable Bool).
- Source detection: response.rawResponse.modelVersion == "apple-foundation-models-system-language-model" for device, Gemini model name for cloud. [V] same page.
- Limits: text only, ~4096 tokens, foreground only. [V] get-started.
- Hosted macOS VMs report .deviceNotEligible; Simulator needs a host Mac on Tahoe with Apple Intelligence on. [R] research/07 line 25-26, native/ios/README.md line 15 [U, not re-verified].

## 2. Mac-free pipeline
Current state [R]: sprout/app/ios does NOT exist. No .github folder. package.json has only @capacitor/android, capacitor.config.json has no ios key, .gitignore already lists app/ios/App/Pods and GoogleService-Info.plist. Capacitor core and CLI are 8.x.

Facts:
- `cap add ios` works on Windows: it generates the ios/ folder, only CocoaPods steps warn; compile/run is impossible on Windows. [V-secondary, vendor blog] https://capgo.app/blog/capacitor-development-on-windows/ . Official Capacitor docs do not state it [V: capacitorjs.com/docs/ios silent]. Safest: run `cap add ios` on the GitHub macOS runner and also commit the result (see step 3) so the project is reproducible.
- Capacitor 8 makes SPM the default for new iOS projects; CocoaPods is opt-in via `--packagemanager CocoaPods`. [V] https://ionic.io/blog/announcing-capacitor-8 and https://ionic.io/blog/swift-package-manager-and-capacitor . Capacitor docs say iOS needs Xcode 26.0+. [V] https://capacitorjs.com/docs/ios . Choose SPM: Firebase hybrid is SPM-only anyway, and CocoaPods trunk goes read-only Dec 2 2026 [V-secondary, RevenueCat docs via search].
- GitHub runner: label macos-26 (arm64); default Xcode 26.6 at /Applications/Xcode.app; 26.5, 26.4.1, 26.3, 26.2, 26.1.1, 26.0.1 also installed; Xcode 27 is only a public preview announcement, not installed; fastlane 2.242.0, CocoaPods 1.17.0. [V] https://github.com/actions/runner-images/blob/main/images/macos/macos-26-arm64-Readme.md ; macOS 26 GA for hosted runners: https://github.blog/changelog/2026-02-26-macos-26-is-now-generally-available-for-github-hosted-runners/ . Use `macos-26` and `sudo xcode-select -s /Applications/Xcode_26.6.app` (any >= 26.2 works for Firebase 12.x).
- Cost: standard hosted runners are free in public repos [V, billing doc says so without naming macOS; hackathon requires a public repo anyway]. A private repo bills macOS at $0.062/min. [V] https://docs.github.com/en/billing/concepts/product-billing/github-actions
- SPM trap: the Swift file as written needs Firebase added to the Xcode project, which means editing project.pbxproj by hand on Windows. Better: make the plugin a local Capacitor SPM plugin (npm package folder `plugins/sprout-ai` with its own Package.swift that depends on firebase-ios-sdk `"12.13.0"..<"13.0.0"` and capacitor-swift-pm, source under ios/Sources/). `pnpm add ./plugins/sprout-ai` then `cap sync ios` wires it into CapApp-SPM automatically ("The Capacitor CLI will modify the CapApp-SPM package when you sync new plugins", [V] https://capacitorjs.com/docs/ios/spm). This removes both the pbxproj edit and the registerPluginInstance/storyboard step (README steps 4-6). Exact plugin package layout is [U]; fall back to registerPluginInstance if it does not register.
- Signing without a Mac, two options:
  A (recommended, deterministic): one-time manual certificate. On Windows (openssl ships with Git for Windows): `openssl genrsa -out dist.key 2048`, `openssl req -new -key dist.key -out dist.csr -subj "/emailAddress=<apple id email>/CN=Sprout/C=US"`; upload CSR at developer.apple.com > Certificates > Apple Distribution; download dist.cer; `openssl x509 -inform der -in dist.cer -out dist.pem`; `openssl pkcs12 -export -inkey dist.key -in dist.pem -out dist.p12`. Create App ID (dev.sprout.kids, capability App Attest) and an App Store provisioning profile on the website. Store base64 of dist.p12, its password, the .mobileprovision, and the API key as GitHub secrets. [U for exact openssl flags; flow is standard. Capawesome also offers a browser CSR/.p12 generator, https://capawesome.io/tools/ios-certificate-generator/ [V exists, not tried]].
  B: let CI make it: fastlane `cert`/`sigh` with an App Store Connect API key (supports API key per https://docs.fastlane.tools/app-store-connect-api/ [V]); `cert` generates the CSR itself [U]. Risk: ephemeral runner creates a new Distribution certificate every run, Apple caps the count; fastlane recommends `match` (needs a private certs repo). Option C: `xcodebuild -allowProvisioningUpdates -authenticationKeyPath/ID/IssuerID`, but Apple forum reports of "no profile found" on clean CI machines make it fragile [V-forum] https://developer.apple.com/forums/thread/764554 . Use A.
- Upload: `xcrun altool --upload-app -f App.ipa -t ios --apiKey <id> --apiIssuer <issuer>` (needs the .p8 at ~/private_keys/AuthKey_<id>.p8) or `fastlane pilot upload` with api_key. [V-secondary: https://ionic.io/docs/tutorials/integrations/github-actions/send-to-testflight and https://docs.fastlane.tools/actions/pilot/]. API key must be a Team key with App Manager (or Admin) access, an Individual key does not work [V-secondary, search summary].

## 3. TestFlight external link and beta review
- Public link: Testers tab of the external group > Create Public Link; tester limit 1-10,000; no email needed; testers appear anonymous; can be disabled any time. A group is needed, and an internal group must exist first. [V] https://developer.apple.com/help/app-store-connect/test-a-beta-version/invite-external-testers/
- Beta App Review required for the first build of each version; up to 6 submissions/24 h; one in review at a time. [V] same page.
- Review time: Apple publishes none. 2026 forum reports: normally 24-48 h, first builds reported at about 65 h, 3 days, and 2+ weeks. [V-forum] https://developer.apple.com/forums/thread/838378 , https://developer.apple.com/forums/thread/837610 , https://developer.apple.com/forums/thread/826089 . Conclusion: submit for review by Nov 27 morning at the latest; it may not clear before Nov 30. Internal testing (up to 100 internal users via App Store Connect roles, no review) works immediately after processing [U for the 100 figure], useful for your own demo recording but not for judges.
- Build expiry 90 days [U, not shown on fetched page]. Fine through the judging period (to Dec 16).
- Judges "may judge solely on text, images and video" and are not required to test [V] research/00-hackathon-official/devpost-rules.txt line 60. So TestFlight is a bonus; do not make the submission depend on it.

## 4. Free sideload alternative (Windows)
- Sideloadly (Windows) or AltStore with a free Apple ID: IPA must be signed; app works 7 days then needs re-sign; max 3 sideloaded apps; 10 App IDs per 7 days (Corellium says resets every 4 days, conflicting); 3 device UDIDs per 7 days; iPhone needs Developer Mode on. [V-vendor] https://sideloadly.io/faq , https://support.corellium.com/features/apps/sideloadly . iTunes for Windows requirement not confirmed this session [U].
- Needs an unsigned/ad hoc IPA from CI: build with `CODE_SIGNING_ALLOWED=NO` on macos-26 and upload as artifact; Sideloadly re-signs it. No $99 needed. Works only if someone owns/borrows an iPhone.
- Limits for Sprout: free accounts cannot use paid-only capabilities. App Attest on a free Personal Team is unconfirmed [U]; assume not, and use the App Check DEBUG provider (debug token registered in Firebase console; allowed in submissions per devpost-rules.txt line 55). A free-signed build also cannot go to TestFlight and judges cannot install it.
- Apple Intelligence still needs iPhone 15 Pro or newer, iOS 26, English region; otherwise the app shows the cloud path only.

## 5. Review of native/ios/SproutAiPlugin.swift (file:line)
README VERIFY items that the docs now settle [V get-started + configuration-options]: `FirebaseAI.firebaseAI(backend: .googleAI())` (line 30) correct; `ai.geminiModel(name:)` (127) correct; `FirebaseAI.SystemLanguageModel.default` (126) correct; `.hybridModel(primary:secondary:)` (137, 139) is the documented form; `response.content` (114) and `session.respond(to:)` (105) correct; `rawResponse.modelVersion` and the "apple-foundation-models-system-language-model" string (111-112) correct; module `FirebaseAILogic` (3) correct.
Concrete risks:
1. Lines 4, 38, 126: no `@available(iOS 26, *)`. Capacitor templates default to a low deployment target (iOS 15 per https://capacitorjs.com/docs/ios [V]); `SystemLanguageModel` is iOS 26+, so compile fails with "only available in iOS 26.0 or newer". Fix: set IPHONEOS_DEPLOYMENT_TARGET 26.0 (drops older phones, acceptable since cloud-only phones would lose the story anyway) or guard with `if #available(iOS 26, *)` and `@available` on makeSession; also `import FoundationModels` is then fine. [U exact annotation on Firebase types]
2. Lines 60, 99: `Task {}` captures non-Sendable CAPPluginCall and self; fine in Swift 5 language mode, errors in Swift 6 mode. Keep SWIFT_VERSION 5 in the app target, or mark `@MainActor`/copy values out before the Task. [U]
3. Line 38: availability is read from Apple's SystemLanguageModel, but inference goes through Firebase's wrapper; docs expose `FirebaseAI.SystemLanguageModel.default.availability` (configuration-options page). Use the Firebase one so status and routing agree.
4. Lines 42-45: `.appleIntelligenceNotEnabled` maps to "unavailable"; prepareDevice then rejects with "needs iPhone 15 Pro or newer" (line 72), wrong message for a user who only has to enable Apple Intelligence. Return a distinct reason string for the JS side.
5. Lines 68-70: progress is a fixed 0.0 every 2 s; harmless, but the UI will show a stuck bar. Emit nothing or an indeterminate flag.
6. Line 28: model name hardcoded "gemini-3.8-flash"; matches research/02 and free tier [R], but line 27 comment says to sync with Remote Config and does not. Accept a `cloudModel` param from JS.
7. Lines 125-139: `try` and `throws` only for the default branch; fine. `only_device`/`only_cloud` pass a bare model to generativeModelSession(model:); docs say one model is allowed [V] but the exact overload is [U]; compile will tell. Also modelVersion for the bare device model may be nil, line 111 handles with `?? ""` (warning if non-optional).
8. Line 102-117: errors from the device path (e.g. guardrail violation, context-window exceeded at about 4096 tokens) all become a generic reject; the JS pipeline fails closed, fine, but pass an error code so Sprout can retry on cloud in prefer_device mode (HybridModel falls back on its own only for unavailability [U]).
9. Plugin does not configure Firebase or App Check; relies on AppDelegate. README line 47 uses `AppAttestProviderFactory()` which I believe is not an SDK class; the SDK provides `AppAttestProvider` and you subclass `AppCheckProviderFactory` yourself [U, verify against https://firebase.google.com/docs/app-check/ios/app-attest-provider]. With SPM-plugin route, put this in AppDelegate.swift edited on the runner (sed) or in the plugin's `load()`; it must run before FirebaseApp.configure().
10. Info.plist (not present, no ios/ yet): needs ITSAppUsesNonExemptEncryption=false, microphone/speech usage strings only if voice is used, and GoogleService-Info.plist injected from secret. Bundle id must match the Firebase iOS app.
11. No `ios` capacitor.config block and no `@capacitor/ios` dependency yet [R]; `src/state.tsx` switching to CapacitorAi is claimed done in README step 10, not checked here.
